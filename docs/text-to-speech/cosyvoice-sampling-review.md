# CosyVoice sampling-version review

Two clean pinned author sources define different sampling behavior. The original 300M rendering reference uses the [v2.0 source tag's common sampler](https://github.com/FunAudioLLM/CosyVoice/blob/8555549e882236e6541748b1042d95693caa82ba/cosyvoice/utils/common.py) and [language-model controller](https://github.com/FunAudioLLM/CosyVoice/blob/8555549e882236e6541748b1042d95693caa82ba/cosyvoice/llm/llm.py). The current CosyVoice 2/3 profile uses [the later sampler](https://github.com/FunAudioLLM/CosyVoice/blob/074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc/cosyvoice/utils/common.py) and [controller](https://github.com/FunAudioLLM/CosyVoice/blob/074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc/cosyvoice/llm/llm.py). A source tag is not a model-generation name: the v2.0 checkout is specifically the oracle selected for original 300M cloning/rendering, not a claim that every historical CosyVoice 2 release has the current rule.

Original 300M RAS resamples the unchanged full distribution when the nucleus draw meets the repetition threshold. The newer source first masks that repeated draw, then resamples. Applying the newer exclusion globally changed the original model. Its existing test incorrectly required exclusion for the original-model configuration. The original `CosyVoiceLmConfiguration` now selects unrestricted fallback by default; current CosyVoice 2/3 scalar sampling retains exclusion, including the author's input-score mutation. The old assertion is replaced with original-author golden outputs.

Both author samplers apply softmax to their incoming scores, including already log-softmaxed or EOS-masked scores. Native sampling previously exponentiated them without stable normalization. This breaks arbitrary logit-shift invariance and changes nucleus membership after EOS masking. It now subtracts the maximum, normalizes explicitly and rejects distributions without a finite unmasked score.

The version difference also affects initial EOS suppression. Original 300M `sampling_ids` repeatedly samples without masking and rejects EOS, failing after 101 rejected draws at its `num_trials > 100` boundary. Current code masks EOS before sampling. These produce different conditional nucleus distributions and random-draw counts. The native original-model generation loop now calls its rejection controller; CosyVoice 2/3 call the mask controller. The distinction is tested rather than inferred from a shared sampler name.

`cosyvoice_sampling_reference.py` executes the unchanged original `ras_sampling`, `nucleus_sampling`, `random_sampling` and `sampling_ids` ASTs from both revisions. Only categorical random quantiles are replayed. Source revisions and both common/controller SHA-256 values are recorded. Twenty-two sampler cases cover repeat windows, thresholds, fallback outcomes, extreme score shifts, raw logits, masked tokens, zero quantiles and input mutation. Eight additional controller cases cover unrestricted EOS, rejection versus masking, their different conditional nucleus outputs, and the rejection limit. Eleven of the initial 22 sampler comparisons fail against old production. All 30 comparisons and the corrected existing original-model test pass against repaired source and the production assembly. Build49 passes both library frameworks and all 411 reviewed cases through the actual repository test project on each of `net8.0` and `net471`, with zero failures or skips. The checkpoint-audit executable also rebuilds successfully after the internal configuration signature change. Both author source/controller hashes match the recorded fixtures and the checked files have no tracked modifications.

The categorical quantiles establish the tested distributions and control flow, not identical Torch/native RNG streams or perceptual free-running quality. They complement the complete original LM checkpoint, frozen frontend, flow and waveform comparisons.

Reproduce:

```powershell
python tools/reference-data/cosyvoice_sampling_reference.py <original-v2.0-checkout> <current-author-checkout>

```
