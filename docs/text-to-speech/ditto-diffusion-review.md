# DiTTo diffusion network review

The sources are [DiTTo sections 3.2–3.3](https://arxiv.org/html/2406.11427), its [official project page](https://ditto-tts.github.io/), the cited RoFormer positional embedding, and the original [DiT timestep implementation](https://github.com/facebookresearch/DiT/blob/ed81ce2229091fd4ecc9a223645f95cf379d582b/models.py). DiT author revision `ed81ce2229091fd4ecc9a223645f95cf379d582b` is pinned; its source-file SHA-256 is stored in the generated fixture.

The adversarial comparison found two differences. Native timestep frequencies divided by `half - 1`; original DiT divides by `half`. The independent timestep check failed with maximum feature error 1.0086. Native RoPE also rotated the combined hidden width before splitting attention heads, causing different heads to receive different frequency bands. Rotary embeddings now operate inside each head, with the frequency basis restarted for each head; an even per-head rotary dimension is required.

`ditto_diffusion_reference.py` executes a complete reduced two-block field using independent PyTorch operators: masked-latent projection, timestep and pooled-text conditioning, learned null text, shared nine-way modulation plus block offsets, rotary self-attention, cross-attention, exact GEGLU, the long skip MLP, and output projection. Conditional and unconditional cases compare every output, the masked velocity objective, all 63 learned parameter gradients, and noisy-latent/text gradients. Both corrected source cases pass at 1e-9.

The original DiT timestep class executes unchanged. Its forced float32 timestep output is retained separately. The strict double comparison uses an explicitly labeled operator-precision run that promotes only requested float32 operations; it does not replace a neural forward method. This is an equation reference for the disclosed diffusion network, not an original KRAFTON checkpoint. Mel-VAE training, semantic finetuning, quantizer/critic gradients and stage ownership have separate reference checks. Private Mel-VAE implementation details remain identified as native choices.

There is a notation ambiguity in DiTTo section 3.1: its velocity definition prints a noised-latent superscript in the subtraction term. Native training and reconstruction use the cited [Salimans–Ho velocity rotation](https://arxiv.org/pdf/2202.00512), section 4 and Appendix D: `v = alpha * epsilon - sigma * clean`, with `clean = alpha * noisy - sigma * v`. This identifies the implemented convention; an unreleased author checkpoint is not certified by resolving that ambiguity.

Build44 passes both library targets (`net8.0`, `net471`). The actual repository test project compiles for both targets and passes the same 356 reviewed tests on each, with zero failures or skips. Both complete DiTTo cases pass against the production assembly as well as the source harness.

The later Build58 review adds complete neural [DDIM sampling references](ditto-sampling-review.md) and repairs the public path's [missing reference transcript](ditto-prompt-review.md). The original field outputs and all gradient fixture fields are unchanged; the current review covers 512 cases on each framework, with the precise run partition recorded in those reviews.
