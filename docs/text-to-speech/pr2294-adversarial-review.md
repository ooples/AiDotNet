# PR #2294: TTS adversarial evidence register (scope corrected)

Scope correction: the previous 18-row register included five supporting implementations while omitting Kokoro, MetaVoice1B, OpenVoice, OpenVoiceV2 and an explicit canonical XTTSv2 entry. The [corrected requested set](pr2294-scope-correction.md) is authoritative. MetaVoice1B now has genuine native GPT/speaker/EnCodec/multiband/DeepFilterNet components, complete raw/enhanced public waveform and fine-tuning comparisons, and production full-checkpoint checks; Build88 passes all 607 selected normal-project regressions on both targets. Kokoro uses the actual native graph and original voice assets, with original float32 DSP buffers now restoring raw waveform parity; the near-empty-bin angular stress diagnostic remains explicit. Both OpenVoice versions now have independent complete training-objective/gradient checks and exclusive public generator/discriminator updates, in addition to released-checkpoint inference evidence; cloning and fresh-instance restoration pass, and both normal 601-case target suites pass; Build88 passes all 607 selected normal-project regressions on both targets. Canonical XTTSv2 passes an explicit full-checkpoint audit through its own public class. Earlier all-18 coverage claims remain withdrawn.

Detailed architectural choices and source/release differences are recorded in [paper-fidelity-decisions.md](paper-fidelity-decisions.md). Expected numerical outputs come from the authors' implementations where available; independent equation references identify themselves explicitly.

Additional adversarial findings after the 279-test production run: Spark's original XLSR checkpoint uses the `wav2vec2.` pretraining namespace and legacy `weight_g`/`weight_v` positional tensors. Both imports were broken. The native XLSR also omitted trained convolution biases and waveform standardization, while its speaker frontend used three seconds instead of the release's six seconds. These failures are repaired and covered by four namespace/weight-normalization cases and a frontend regression; all 16 Spark paper tests pass. The complete original Qwen/XLSR/BiCodec checkpoint audit now passes in the source harness: Qwen logits differ by 3.13e-6 from author float64; XLSR normalization is exact and mixed hidden features differ by 1.92e-11 from the original full float64 backbone. Semantic/global IDs are exact and the entire native waveform-to-codes-to-waveform chain differs by 1.02e-7. The original float32 XLSR hidden-feature delta (0.00906166) is explicitly preserved and reported, rather than silently accepted as float64 equivalence. Raw mel matches the original float64-buffer frontend within 1.99e-14; original upcast-float32-buffer delta is 1.243e-6. The ECAPA network on author features differs by 3.02e-14, Perceiver by 3.56e-15, and speaker reconstruction by 2.56e-15. The full audit also passes against the rebuilt production library.

E3TTS [Equation 6](https://arxiv.org/html/2311.00945#S3.E6) defines the learned variance as a function of noise level. The previous implementation incorrectly added speaker identity to that branch. A regression failed before the repair (same noise level gave log variances -0.051022046422246295 and -0.04435186556151377 for two speakers). The variance head now receives only the timestep representation, while waveform blocks retain speaker conditioning. All 10 E3 tests pass in the source harness, including three independent closed-form checks of the weighted KL-form objective and every prediction/variance derivative to 13 decimal places. These checks do not certify an unpublished complete author U-Net or checkpoint. Both production frameworks have been rebuilt successfully after this correction.

Historical test baseline before the scope correction: Build59 passes `net8.0` and `net471` with no library build errors. The actual repository test project passes its full 520-case reviewed suite on each target, with zero failures or skips; copied-library hashes match the production builds and the checkpoint tool builds cleanly. These cases cover the previously selected register and its corrections, including eight CosyVoice3 DiffRO checks. They do NOT cover faithful implementations of the four omitted placeholder models. Model-file presence and passing existing cases are not completion evidence for those models. The full requested goal remains active; see the [scope correction](pr2294-scope-correction.md) and [completion audit](pr2294-completion-audit.md).

## Findings repaired during adversarial review

- The actual official XTTS checkpoint and tokenizer have 6,681 rows and 17 language tags, contradicting the earlier 6,153-row default/test and 16-language list. Defaults now match the pinned files, including the original Hindi basic-cleaner behavior. The original `model.pth` wrapper also exposed a public loader failure: `model.gpt.*` keys are now unwrapped before importing the networks. Wrapped PyTorch-file regressions verify both GPT latents and conditioner outputs.
- Loading the actual XTTS tokenizer also failed because its Unicode `Whitespace` BPE was sent to a byte-only reader. The shared reader now supports the release's scalar-based BPE, Unicode word/mark boundaries, unknown tokens and decoder-free output. Its 2,053 duplicate merge entries exposed another mismatch: the original Hugging Face reader retains each pair's last rank, whereas the native reader kept the first. An independent Hugging Face tokenizer fixture checks 47 encode/decode cases across this mode and the existing byte-level mode, including Hindi marks, supplementary letters, emoji, join controls, added tokens, unknown-ID merges and duplicate-rank precedence.
- The full XTTS import then exposed Coqui's `cond_layer` versus the generic HiFi-GAN `cond` name. The XTTS-specific decoder now maps that global projection while retaining the original `conds` stage names. A wrapped original PyTorch fixture loads all 51 small author-decoder tensors and reproduces the complete HifiDecoder waveform within 2e-9, including both latent interpolation passes and every speaker projection.
- XTTS used Slaney-spaced mel filters for waveforms, while the original Coqui transforms use torchaudio's default HTK spacing with Slaney area normalization. The direct author-transform regression initially measured error 12.856; repaired conditioning/dVAE transforms now match within 2e-8 in float64 at both released FFT/window configurations. Diagnostic inverse features use the matching filterbank too.
- E3TTS training reused the Eq. 7 inference schedule. Training now interpolates cumulative products of linearly spaced betas as specified in Eq. 4; inference retains Eq. 7. The paper omits training beta endpoints, so these are exposed options with explicitly identified DDPM defaults, not claimed author settings. A regression checks the actual training-example sampler and copied options.
- E3 and DiTTo inherited generic scaled-character `TextToTokens` despite requiring BERT/SentencePiece IDs. Their public token API now returns actual model tokens. Seed inherited the same generic path and then rounded/clamped numeric IDs, collapsing unrelated characters. It now uses a reversible UTF-8 byte frontend (explicitly a native choice because the Seed report does not disclose its text tokenizer) and strictly rejects unsupported/invalid IDs. The cloning facade shares the repaired pipeline.
- Chatterbox T3 trained against already-visible tokens. It now uses next-token targets. Executing the released helper also exposes a CE-axis shape error; the corrected objective follows Resemble's stated autoregressive factorization in [section 2.1, Eq. 2](https://arxiv.org/html/2605.30748v1). Original forward logits and an SGD update match. CFG now retains learned text positions in the unconditional branch.
- Chatterbox's 400-point mel transform produced a speaker-embedding error around 0.002 on a longer reference. Direct Fourier matrices reproduce the original power mel and fix the complete 16 kHz voice-embedding chain. Very short inputs use reflection rather than zero extension; quiet trimming uses librosa's amplitude floor.
- The full released S3Gen checkpoint audit initially failed strict frontend thresholds. Independent precision experiments reproduce those differences: original float32 FFT/window/filterbank arithmetic and forced float32 CAM++ input differ from native float64 on low-energy bins. Separately labeled float64 author-function/network variants and precision-matched author conditioning now verify the native arithmetic without removing the original float32 results or increasing their thresholds. The complete scoped audit passes.
- DiTTo exposed only diffusion and length training despite containing a codec. Its public codec stages now train the actual encoder/quantizer/decoder and both mel-critic families, with a separately loaded frozen ByT5 decoder for semantic finetuning. Codec pretraining accepts untranscribed recordings or prepared mels.
- AlignTTS divided the sequence likelihood by mel length, changing relative objective weights. Its objective now follows the paper's unscaled sequence NLL.
- Voicebox dequantized only duration targets and clipped negative zero-duration draws. Both context and target duration transformations now follow Appendix A.
- VoiceCraft used a substitute English G2P and bypassed supplied phone mapping in synthesis/editing. It now uses the released eSpeak-IPA frontend or an explicit supplied phonemizer, with checkpoint phone IDs honored throughout.
- Spark had incorrect ECAPA/FSQ layouts, incomplete added-token coverage, missing decoder sampling blocks, and control/sampling/training-target mismatches. Independent release execution now covers those components and the output-suffix objective.
- Tortoise had mismatched text/mel/conditioning/diffusion paths and incomplete vocoder training. The repaired components are checked against the original modules, including variance gradients, zero-step likelihood and separate generator/discriminator updates.
- XTTS frontends omitted number grammars and differed in Chinese/Korean/Japanese normalization. Released cleaning and pronunciation behavior now has direct multilingual reference coverage.

## Reproduction boundaries

Reference generators live in `tools/reference-data/`; their JSON and named safetensors fixtures live in `tests/AiDotNet.Tests/TextToSpeech/ReferenceData/`. Tiny deterministic weights verify computations and imports; they are not evidence that the full published pretrained checkpoints have been rendered. Double-precision checks normally use 1e-9 or tighter tolerances; references that force float32 arithmetic identify that behavior explicitly.
