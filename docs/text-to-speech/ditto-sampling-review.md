# DiTTo latent sampling review

The primary source is [DiTTo v2](https://arxiv.org/html/2406.11427v2), sections 3.1–3.2 and appendix A.6. The disclosed settings are shifted-cosine noise, guidance scale 5, and 25 inference steps. Tables 1–2 and section 5.1 separately identify a DDIM variant trained for more steps. They do not disclose sufficient sampler implementation details to certify identity with every reported evaluation configuration.

`ditto_diffusion_reference.py` now generates six complete independent PyTorch DDIM rollouts using the existing two-block, 63-tensor diffusion field. It evaluates both complete neural CFG branches at every step and records every latent state. The cases cover one, two, and 25 steps; guidance 0, 1, and 5; schedule scales 0.3 and 0.5; and no prompt, a partial prompt, and a fully known prompt. Every preexisting forward/gradient fixture field remains unchanged.

`DiTToSamplingReferenceTests` imports all 63 field tensors into the actual native model and compares each complete rollout's final latent against PyTorch at 1e-8. Only the initial Gaussian samples and length posterior are controlled: no neural prediction or sampler update is replaced. Box–Muller replay checks all 32 initial uniform draws were consumed. Prompt samples must remain exactly equal. The length predictor, both neural guidance branches, schedule, velocity inversion, and each DDIM update execute in production code. Synthesis calls the same extracted latent-generation method before Mel-VAE and BigVGAN; existing length-boundary tests continue to exercise the complete waveform path.

The six source cases pass. Deliberately setting CFG to zero fails four cases and passes the two expected invariants (zero guidance and fully known prompt). Removing prompt restoration after each sampler step also fails four cases and passes both unprompted cases. These are mutation checks, not claims of newly discovered production defects.

The finite endpoint clamp (`1e-9` before shifting the cosine power) is an explicit native numerical policy included in this reference. The implemented velocity convention is the canonical Salimans–Ho rotation described in [the diffusion review](ditto-diffusion-review.md). This verifies the implemented deterministic DDIM path; it does not establish original KRAFTON checkpoint parity or undisclosed evaluation-sampler identity.

Build58 passes both library targets with zero errors. The 512-case production-assembly suite passes on net8.0. The actual repository test project also compiles on both targets: net8.0 passes all 512 cases in one run; net471 passes the 511-case suite plus the subsequently added public-routing case, with unchanged production code. All six sampler cases are included in both target suites. There are zero test failures or skips. SHA-256 checks confirm each target's copied test library equals its corresponding production build. The checkpoint-audit tool builds with zero warnings or errors.
