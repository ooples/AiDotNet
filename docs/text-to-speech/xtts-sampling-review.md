# XTTS-v2 generation-policy and latent-replay review

The primary source is [Coqui's GPT implementation](https://github.com/coqui-ai/TTS/blob/dbf1a08a0d4e47fdad6172e433eeb34bc6b13b4e/TTS/tts/layers/xtts/gpt.py) and its [public inference path](https://github.com/coqui-ai/TTS/blob/dbf1a08a0d4e47fdad6172e433eeb34bc6b13b4e/TTS/tts/models/xtts.py). The requirements allow Transformers >=4.33.0. The reference executes the original 4.33.0 processor bodies from an uninstalled wheel; this is the supported lower bound, not an exact author dependency pin.

`tools/reference-data/xtts_sampling_reference.py` executes the actual `compute_embeddings` body. Controlled embeddings expose the original fake prefix IDs: condition/text positions contain ID 1 and the final input is audio BOS. HF repetition penalties therefore see both IDs from the first step, as well as subsequently generated IDs. The old native sampler receives only generated codes. Original repetition, temperature, top-k and top-p processor bodies produce twelve probability distributions covering released defaults, positive/negative penalties, temperature, tied cutoffs, nucleus boundaries and zero top-p. The fixture records author, wheel, policy and pipeline hashes and verifies original temperature/top-k/top-p order.

The generator additionally executes original `generate`, `forward`, `set_mel_padding` and `set_inputs_and_targets` bodies with controlled network outputs tagged by token ID and position. This checks formatting and replay independently of learned network numerics. HF returns the selected EOS in the generated sequence. The original forward routine pads the sequence and removes its final five states; it retains one prediction latent per generated ID, including EOS. Immediate EOS therefore has one latent, rather than an empty waveform boundary. A speech-then-EOS case verifies two latents, and a capped raw-BOS sequence verifies that special IDs are preserved during replay.

The repair includes the fake prefix IDs in repetition history, keeps every top-k threshold tie, applies the independently verified HF ascending-tail nucleus rule, and allows top-p zero at the native option boundary. Generated IDs remain unchanged, including BOS and terminating EOS. The EOS prediction state is retained for the waveform decoder. The old code clamped a sampled BOS to a codec ID, omitted terminal EOS and substituted code zero when EOS arrived immediately.

`XttsSamplingReferenceTests` compares twelve source distributions at 72 fixed categorical quantiles and both sides of resolved active CDF boundaries at 1e-9. Five regressions run the actual reduced GPT with a controlled learned head and compare returned IDs and latent counts with the original formatting/replay traces. A final case checks the native option boundary. Ten of eighteen tests fail against the previous production assembly; all eighteen pass against the repaired source.

These tests complement the full released GPT, H/ASP, dVAE and waveform-decoder checkpoint comparisons. Controlled head values and tagged reference outputs establish controller/replay behavior, not trained speech quality, identical arbitrary GPU tie ordering or identical categorical random streams.

The production checkpoint tool now also supports `xtts-canonical`, which constructs the public `XTTSv2<double>` class directly rather than its `XTTSv2Clone` subclass. The complete original-checkpoint comparison passes through that canonical instance against release `6c2b0d75eae4b7047358e3b6bd9325f857d43f77` and Coqui code `dbf1a08a0d4e47fdad6172e433eeb34bc6b13b4e`: original tokenizer IDs and dVAE code IDs match, dVAE reconstruction error is `9.99e-16`, decoder error on author features is `8.44e-15`, and the native GPT/speaker-to-waveform error is `1.09e-6`. GPT and waveform-frontend float32/buffer differences are reported separately by the audit rather than represented as exact equality. The cloning facade's prior independent full-checkpoint comparison remains additional coverage.

Build53 compiles the production library on net8.0 and net471 without errors. The normal repository test project passes all 456 reviewed cases on each target, with zero failures or skips. The checkpoint-audit tool also builds without errors.
