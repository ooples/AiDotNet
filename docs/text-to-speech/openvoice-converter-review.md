# OpenVoice and OpenVoiceV2 adversarial inference and training review

The four models omitted from the previous review register included both OpenVoice releases. Their former native text/waveform and speaker transforms were placeholders. The public classes are retained and now route through a native reference encoder and the actual shared converter. Their base synthesizers remain separate, as [the paper's section 2.2](https://arxiv.org/html/2312.01479v5) specifies: native VITS by default for OpenVoice, native MeloTTS for V2, or an explicitly supplied `ITtsModel<T>` through `BaseSynthesizer`. MeloTTS audio is resampled to the converter's 22050 Hz with the repository's native librosa-compatible SoXR implementation.

The source of truth for implementation details is [myshell-ai/OpenVoice](https://github.com/myshell-ai/OpenVoice/tree/74a1d147b17a8c3092dd5430504bd83ef6c7eb23), particularly `openvoice/models.py`, `modules.py`, `mel_processing.py` and `api.py`. The released converters are pinned to `myshell-ai/OpenVoice` revision `c70fc8b939bd1d8213994ff7c88e32be39708271` and `myshell-ai/OpenVoiceV2` revision `f36e7edfe1684461a8343844af60babc2efbb727`.

The reference encoder reads **linear STFT magnitudes**, applies frequency layer normalization, six weight-normalized stride-two 2D convolutions with widths `[32,32,64,64,128,128]`, a 128-wide PyTorch GRU and a speaker projection. It does not normalize the output vector. PyTorch's reset-after recurrent candidate and its separate recurrent bias are essential; the existing Tacotron-style reset-before GRU cannot load these weights faithfully. Both normalization settings have independent complete-output and all-parameter/input-gradient fixtures from the unchanged author forward. Tests use odd lengths, batch two and three recurrent steps, retaining all convolution widths and the original GRU width.

The converter retains the 16-layer posterior WaveNet, four mean-only coupling blocks each with four WaveNet layers, channel flips in the correct forward/inverse order and speaker-conditioned VITS HiFi-GAN. Explicit posterior noise makes the comparison reproducible. The V2 `zero_g` setting zeros only the posterior/decoder speaker input; the flow still receives the source/target embeddings. Condition layers and their learned biases remain present when the input is zero.

`openvoice_converter.py` executes the unchanged complete author `voice_conversion` method for both versions, retaining all posterior and coupling layers with reduced widths and vocoder depth. The two masked unequal-length batches compare all intermediate latents, waveform, every learned tensor gradient, spectrogram/source/target/noise gradients and flow inversion. Together with the two reference-encoder cases, the first four independent tests pass. These are mathematical comparisons against the original implementation, not shape-only tests.

`openvoice_released_checkpoint.py` downloads the pinned original `.pth` checkpoints and requires zero missing and unexpected tensors when loading the author's actual full model. Both contain 486 tensors, including reference-encoder layer normalization. `OpenVoiceAudit` imports all 486 into native modules and compares the full reference encoder, posterior/prior/converted latents and decoded waveform. Maximum double-precision errors were `4.9e-15` for V1 and `6.3e-15` for V2 on author features. The audit also loads the original wrapped `.pth` through the native waveform API and compares raw-audio speaker extraction and complete conversion: maximum errors `2.84e-14` for V1 and `4.92e-14` for V2 with matched window precision. Both comparisons pass through the actual Build61 production library and repository checkpoint tool. Three additional public routing/options tests bring the dedicated test count to seven.

The raw waveform frontend exposed a precision detail rather than a neural mismatch: the author's `torch.hann_window` constructs a float32 window before converting it to a double audio dtype. The native double frontend constructs its window in double. The initial raw-source embedding difference was `1.99e-8`; that failed audit is retained. The generator stores both the original float32-window outputs and a separately labeled double-window comparison, using the unchanged original frontend in both cases. The actual repository audit tool prints both comparisons: original float32-window speaker-vector drift reaches `8.90e-8`, waveform drift `5.98e-8`. No neural forward is replaced and no tolerance is relaxed to hide that distinction.

The native training path now implements section 2.3 separately from inference: direct posterior-to-decoder waveform reconstruction, a speaker-free IPA-token Transformer prior, detached monotonic Gaussian alignment, the volume-preserving flow KL, mel reconstruction, least-squares adversarial losses and feature matching. The caller supplies token IDs for its universal IPA inventory; the released repository does not publish the private auxiliary training inventory or fitted prior/discriminator weights. Configurable VITS/HiFi-GAN loss and optimizer settings are explicit native baseline choices, not recovered unpublished OpenVoice settings. The default discriminator widths retain the original VITS architecture.

Independent checks now cover both versions' direct reconstruction and KL branches, all 253 converter parameter gradients, and all 39 reduced-prior parameter gradients, including observed original training dropout masks. `openvoice_objective_reference.py` additionally executes the unchanged author reference encoder, posterior, flow, decoder and text encoder plus unchanged original VITS discriminator forwards. Its explicitly reduced convolution widths permit complete double-precision loss and generator/discriminator-gradient comparisons in routine tests. The frontend and mel-loss magnitude use the author's `1e-6` square-root epsilon; an initially inherited HiFi-GAN `1e-9` default was found and corrected. The mathematical reference records float64 mel-filter coefficients separately from original float32 frontend drift.

Public `Train` now accepts IPA-token IDs and a target recording through the framework's training hook, registers the auxiliary modules lazily, and performs distinct discriminator and generator AdamW steps. Both versions pass tests proving that each phase updates only its selected parameter group, lazy registration invalidates the parameter-count cache, evaluation is finite and restores the prior training mode, and evaluation does not advance the training step. Deep copying and deserializing into a fresh inference-only instance preserve all auxiliary parameters and the evaluation objective. The latter regression exposed a genuine stale-graph bug: flat weight equality passed, but evaluation originally created a new IPA prior; restored parameters now reconnect to the auxiliary graph before use. The combined source-linked component/objective/public-training/persistence suite passes ten tests. Both production targets compile these changes, and the normal repository project passes the full selected 601-case suite on each framework, including these public training and restoration regressions. The expanded 607-case current-production suite also passes; both final Build88 normal-project targets pass all 607 selected cases with zero failures or skips, as recorded centrally in the completion audit. Optional external watermarking is not implemented or claimed. No model has been removed.
