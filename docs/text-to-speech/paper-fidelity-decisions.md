# Text-to-speech: paper-fidelity decisions

Each text-to-speech model, vocoder and neural audio codec listed here implements one published model. This page
records, for each one, where its defaults and behaviour come from, and every place where the code had to choose.

## How the choices were made

1. **The paper wins where it is explicit.** If a paper states a value or an equation, the code uses it, even when
   the official code does something else. Each such case is listed under *Choices* below.
2. **The official implementation fills the gaps.** Papers leave out many details: padding, initialization, feature
   extraction, optimizer settings. Those come from the authors' released code. If the authors released no code, a
   named reproduction is used instead, and the entry says which.
3. **Nothing is invented.** If neither the paper nor any reference states a value, the option is left for you to
   set, and the entry says so.

The full detail, with section, table and equation numbers, is in each model's XML documentation: the `<remarks>` of
the model class and of its options class. This page summarizes it. When the two disagree, the code documentation is
the one to trust, and this page should be corrected.

## Training data a model needs

Most models train from text and a target spectrogram or waveform. These need more, because their paper takes it from
outside the model. Calling plain `Train(tokens, mel)` on them throws; pass a `TtsTrainingSample` instead.

| Model | What it needs, and why |
|---|---|
| FastSpeech, FastSpeech 2, ProDiff | Phoneme durations. The papers take them from a teacher model or a forced aligner (MFA). |
| SpeedySpeech | Phoneme durations, from its teacher network's attention (§3.1). |
| ForwardTacotron | Phoneme durations, from a Tacotron's attention. |
| Non-Attentive Tacotron | Phoneme durations (this is the supervised-duration variant). |
| PortaSpeech | Phoneme durations, summed per word. |
| VoiceFlow | Phoneme durations from a forced alignment (§3.1, §4.1). |
| AdaSpeech, AdaSpeech 2 | Phoneme durations and the speaker's ID. |
| Tacotron, Deep Voice 3 | The recording, or its linear spectrogram, which a mel spectrogram does not contain. |
| SpeechTokenizer | The self-supervised teacher's features for each clip (the HuBERT distillation target). |
| Pheme | The recording's SpeechTokenizer codes (or the recording, which it encodes), and for the speaker embedding a recording of the speaker. Synthesis needs a voice: a prompt recording and, optionally, its transcript (`CreateVoice`). |
| VALL-E | The recording's EnCodec codes (or the 24 kHz recording, which it encodes). The paper crops each utterance to a random 10–20 seconds with its aligned phonemes; that needs the alignment, so it is left to you. Synthesis needs a voice: a prompt recording and, optionally, its transcript (`CreateVoice`). |
| VALL-E X | As VALL-E, plus the utterance's language (`LanguageId`) and the codes of another sentence by the same speaker (`PromptCodecTokens`), which the NAR model reads as its prompt (Eq. 2). |
| SoundStorm | The utterance's semantic tokens at the codec's frame rate (w2v-BERT k-means tokens in the paper) followed by its SoundStream codes, or the semantic tokens and the recording, which it encodes. Synthesis with a voice needs the prompt recording and its 25 Hz semantic tokens. |
| CosyVoice | The utterance's S3 speech tokens (or the 22.05 kHz recording, which the S3 tokenizer encodes) and the speaker's CAM++ x-vector (`SpeakerReference`, or a recording CAM++ embeds). The flow stage also needs the mel (or the recording), the vocoder stage the 22.05 kHz recording (F0 from it unless `Pitch` is given). `CurrentStage` selects the language model, the flow or the vocoder, trained in turn as the recipe does. |
| CosyVoice 2 | As CosyVoice, at 24 kHz: the utterance's S3 v2 tokens (25 Hz, or the recording) and its CAM++ x-vector; the flow stage the mel (or the recording), trimmed with the tokens to two frames per token; the vocoder stage the 24 kHz recording. `CurrentStage` selects the language model, the flow or the vocoder. |
| Parler-TTS | The recording's DAC codes (or the 44.1 kHz recording, which it encodes) and a description of how it sounds, as T5 token ids (`Description`; `Tokenize` gives them). The paper writes its descriptions from measured pitch, speaking rate, noise and reverberation (§3.1); that annotation is outside the model, so the descriptions are yours to supply. Synthesis needs a voice: a description (`CreateVoice`). |
| KaniTTS | The transcript as the text tokenizer's ids (`TextToTokens` gives them) and the 22.05 kHz recording (`Audio`) or its NanoCodec codes (`CodecTokens`, `[frames, 4]`); a sample's `SpeakerId` picks a name from `SpeakerNames` for the release's "speaker: text" prefix. Load the language model (`LoadReferenceWeights`, which also reads the checkpoint's `tokenizer.json` and speaker list) and the codec (`LoadCodecWeights`, NeMo's `.nemo` file) first. Synthesis speaks as `Speaker`, the voice's speaker, or no speaker. |
| OuteTTS | The 24 kHz recording and its transcript as the language model's token ids (`TextToTokens` gives them). Training builds the release's training prompt from the recording's speaker profile (the transcript's words timed by Whisper, the DAC codes and features) and scores the completion after `<|audio_start|>`. Load the language model (`LoadReferenceWeights`, which also reads Llama-OuteTTS's `tokenizer.json`), the codec (`LoadCodecWeights`) and Whisper large-v3-turbo (`LoadAlignerWeights`) first. Synthesis continues a speaker profile (`Speaker`, such as `OuteTTSSpeaker.DefaultEnglishFemale()`, or one `CreateSpeaker` makes from a recording) or none. |
| PromptTTS | FastSpeech 2's phoneme durations (and the recording or its pitch and energy), and the style prompt as bert-base-uncased token ids (`Description`; `TokenizeStyle` gives them). The style encoder trains first, on each prompt's style-factor labels, through `TrainStyle`. Synthesis needs a voice: a style prompt (`CreateVoice`). |
| EmotiVoice | The phoneme ids (`TextToTokens` gives them from Chinese or English text, by EmotiVoice's own front end), the 16 kHz recording, the speaker id and the emotion prompt as SimBERT token ids (`Description`; `StyleTokens` gives them), and optionally the transcript's SimBERT ids (`Transcript`) for the content embedding; without it the content is an empty text's. Pitch, energy and the alignment come from the recording. The style encoder trains first, on each prompt's pitch, speed, energy and emotion labels, through `TrainStyleEncoder`; or load the released one (`LoadStyleEncoderWeights`). Synthesis needs a voice: a speaker of the released list (by index or name, such as "8051") and a prompt (`CreateVoice`). |
| StyleTTS | Only the phonemes and the recording's mel spectrogram (or the 24 kHz recording, which it converts), so a token/mel pair is a full sample. Train the reconstruction stage first, then set `CurrentStage` to `Prosody` for the duration and prosody predictors. The released text aligner and pitch extractor (`LoadAlignerWeights`, `LoadPitchExtractorWeights`) are the paper's pre-trained starting points. Synthesis needs a voice: a reference recording (`CreateVoice`). |
| StyleTTS 2 | The phonemes (framed by the pad symbol) and the 24 kHz recording; for the multispeaker model, optionally another recording of the same speaker as `SpeakerReference`. Train `Pretraining` first, then set `CurrentStage` to `Joint`. Load the released PL-BERT, text aligner and pitch extractor (`LoadBertWeights`, `LoadAlignerWeights`, `LoadPitchExtractorWeights`) and WavLM-base-plus (`LoadSlmWeights`) first. The multispeaker model synthesizes in a voice (`CreateVoice`); the single-speaker one needs none. |
| StyleTTS-ZS | The phonemes (framed by the pad symbol) and the 24 kHz recording; its prompt is a segment of the same recording. Train with `CurrentStage` at `Training`, then `Distillation` for the one-step student. Load PL-BERT, the aligner, the pitch extractor, WavLM-base-plus and a WeSpeaker ResNet34 first. Synthesis needs a voice: a few seconds of the speaker (`CreateVoice`). |

Pitch, energy and the mel target are derived from the recording when you don't supply them, the way each paper
derives them.
