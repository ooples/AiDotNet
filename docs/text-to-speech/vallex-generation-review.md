# VALL-E X community generation-controller review

The source is [the pinned community implementation](https://github.com/Plachtaa/VALL-E-X/blob/3faaf8ccadb154d63b38070caf518ce9309ea0f4/models/vallex.py), matching the original-file checkpoint comparison. This is a community reproduction; it does not certify unreleased Microsoft weights or private implementation details. Its default `best_of` is one. The native one-candidate path is compared with that default.

`tools/reference-data/vallex_generation_reference.py` executes the unchanged original sampler helpers and complete autoregressive `while` body with controlled neural logits. It also executes the original post-loop code extraction. Four cases cover one/two text tokens with and without audio BOS. The constant learned-logit maximum is code zero, preventing EOS so that the real loop's length boundary is exercised. Source revision/hash and Torch version are recorded.

The original length check is `(y.Length - prompt.Length) > 16 * text.Length` before appending the current sampled token. Because `prompt` was saved before BOS insertion, BOS contributes to that difference. One text token permits 16 new codes with BOS and 17 without it. Native generation passed the 17-code limit in both cases. The repair adjusts the community facade's limit when the actual core prepends BOS; the other path retains its existing limit.

Four additional sampler references execute original temperature/top-k filtering and softmax while capturing the categorical probabilities. Native cutoff ties already match and are preserved. A valid zero native random draw could select the first vocabulary entry even if its masked mass was zero. The repair skips zero-mass entries and uses a positive-mass fallback, preserving existing positive-boundary behavior. A fixed categorical quantile is a distribution/support reference, not a claim of identical Torch/native random algorithms.

`VALLEXGenerationReferenceTests` runs the actual canonical cloning generation path, including native AR/NAR networks and the community prefix configuration. Controlled learned weights create the unique code-zero maximum used by the author-loop reference. It checks code counts and actual first-codebook IDs. Two BOS-dependent cap cases and the masked-zero sampling case fail on the old production assembly: three failures and five passes. All eight pass against the repaired source. The test uses the same inference no-gradient scope as the rendering path.

The learned-network and codec comparisons remain separate full-checkpoint evidence. These controlled cases do not certify speech quality, non-default multi-candidate selection, cross-device stochastic identity or the original Microsoft system.

Expanding the shared-core regressions exposed two pre-existing failures in the older VALL-E fixture adapter, also reproduced against Build53. Its Python generator deduplicates tied NAR head aliases in safetensors and restores them before loading the author model. The C# adapter now resolves the same aliases from the fixture's sharing configuration and verifies every stored tensor was consumed. Original AR/NAR logits, losses and greedy inference comparisons pass, and an intentionally disagreeing tied head is still rejected. These checks use the original stored weights and expected outputs.

Build54 compiles the production library on net8.0 and net471 without errors. The normal repository test project passes all 482 reviewed cases on each target, with zero failures or skips. The checkpoint-audit tool builds without warnings or errors. The expanded suite includes the affected VALL-E/VALL-E2 model regressions and original numerical parity tests; the compact reference fixture's hash matches the pre-repair snapshot.
