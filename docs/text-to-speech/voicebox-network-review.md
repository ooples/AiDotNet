# Voicebox network review

The primary source is [Le et al., Voicebox](https://arxiv.org/html/2306.15687), especially sections 3.3/5.1, Appendix A.6, and Tables D13/D14. The symmetric ALiBi implementation is retained: equal distances have equal biases, and both directions involving the flow-step token have zero bias. The paper links the [ALiBi author's symmetric implementation](https://github.com/ofirpress/attention_with_linear_biases/issues/5).

`voicebox_network_reference.py` independently executes the complete reduced audio and duration networks with PyTorch. It includes the convolutional position stack, every Transformer block, channel-concatenated symmetric skips, phone/context projections, flow-step representation, and both masked objectives. Conditioned and fully unconditioned cases check that dropped inputs and embeddings receive zero gradients. All 128 learned tensor gradients and gradients of the audio state and both contexts are compared.

The new reference failed against Build41: maximum audio-vector-field differences were 2.15e-4 and 1.08e-4. The code used AiDotNet's generic tanh-approximate GELU, while PyTorch/fairseq GELU uses the Gaussian-CDF form. Voicebox now calls the existing `ActivationHelper.ExactGelu` for both convolutional positions and feed-forward layers. [Fairseq's activation source](https://github.com/facebookresearch/fairseq/blob/main/fairseq/modules/gelu.py) explicitly distinguishes these two operations. Both complete source-harness and production cases now pass at 1e-8 for outputs, masked objectives and every gradient. Build42 passes all 348 tests; the subsequent Build44 passes both library targets and all 356 integrated tests.

This does not establish equivalence to Meta's unreleased weights or private source. Reduced dimensions and layer counts retain the disclosed connections. The exact sinusoidal timestep convention and positional-convolution weight-normalization axis are explicitly native choices; the paper's architectural citation does not prove those private choices. Separate scalar OT-CFM, duration dequantization and masked-loss equation tests remain in place. No author checkpoint is invented or a third-party reproduction presented as the original.

The public text path was subsequently found to be hardwired to ARPAbet although section 5.1 specifies MFA's modified IPA. Voicebox now accepts a dataset/checkpoint's exact PhoneVocabulary and an external MfaWordPhonemizer supplying each word's phones. Synthesis, public phonemization and forced-aligned prompt enrollment all use that same path. Native processing preserves IPA strings, adds all four word-position suffixes and boundary/ghost SIL tokens, accepts the inventory's actual SIL ID, and rejects missing symbols or overlong sequences rather than substituting an unknown ID or truncating an alignment. The ARPAbet frontend remains available only through explicit UseNativeEnglishFallback opt-in; it is not claimed to be the MFA frontend. Explicit phone-ID inference and training remain available independently.

Independent paper-example tests cover these transformations, unknown/backend guards and an actual public enrollment-to-waveform call. An adversarial persistence regression changes a phone ID in the destination before restoring a saved model. It exposed that a mutable options dictionary alone did not restore the materialized inventory. The model now owns that dictionary as state and rebuilds its tokenizer after restoration. All 13 Voicebox frontend and existing paper tests pass against the production library, including restoration of the exact original IDs. This API does not invent Meta's private dictionary or replace the externally required MFA alignment/data preparation.
