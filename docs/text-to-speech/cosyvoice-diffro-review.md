# CosyVoice 3 differentiable reward training

The completion audit found that original-checkpoint inference and supervised LM/flow/HiFT training did not implement [CosyVoice 3 section 2.2](https://arxiv.org/html/2505.17589v2#S2.SS2). Equations 3-7 specify differentiable Gumbel-Softmax speech predictions, a token-domain ASR or multi-task log reward, and a summed forward token-level KL penalty against a reference policy. The released `forward_dpo` training route is a different objective and is not substituted for DiffRO.

`CosyVoice3.TrainDifferentiableReward` now teacher-forces the real Qwen policy on the transcript and ground-truth S3 tokens, extracts acoustic-code predictions, and minimizes negative log reward plus beta times token KL. The reference policy executes without gradients and the tensor objective also detaches its reference logits. The reward runs in evaluation mode while retaining input derivatives, so gradients reach Gumbel predictions and the real policy. The normal training/optimizer path selects LM parameters only and restores the caller's previous stage. Reference, reward, flow and HiFT weights are excluded from updates. Reference/reward parameter aliases are rejected. Exceptions restore frozen-model modes and the previous stage.

`ICosyVoiceTokenReward` supports differentiable token-domain task rewards. The concrete `CosyVoiceToken2TextReward` supplies an actual trainable encoder/decoder: soft speech distributions multiply a learned speech table, a bidirectional T5 encoder produces memory, and a causal teacher-forced text decoder supplies summed log likelihood. It has native converted-weight loading and real paired-token SGD pretraining. This configurable T5 realization is explicitly native; the authors did not release their reward architecture or weights. The input and target vocabularies must match the supplied training data. Default beta 0.1, temperature 1 and a finite uniform-noise endpoint clamp are numerical choices, not certified author settings. The policy distribution is conditional on valid acoustic-code categories; EOS, fill and reserved output rows are excluded from the acoustic reward sequence and KL support.

`cosyvoice_diffro_reference.py` executes unmodified Hugging Face `Qwen2Model` and `T5ForConditionalGeneration` forwards in PyTorch. A labeled operator-precision run promotes forced float32 operations for the native double comparison; no neural forward is replaced. The fixture stores package versions, source hashes and complete fixed weights. Three beta/temperature cases compare real teacher-forced logits, Gumbel probabilities, summed KL, complete autoregressive reward, total objective, all 16 policy and 27 reward tensor gradients, soft-token gradients and all 16 reference gradients (zero). A fourth reference checks actual reward-model SGD and every updated tensor. All pass at 1e-8 or tighter.

Four public-API source tests also pass: policy-only updates with frozen-weight/mode/stage checks; deterministic evaluation without consuming training noise; exception restoration without a weight update; and rejection of reward/policy aliases. The public tests instantiate the real native policy, flow and vocoder with reduced valid dimensions.

Mutation checks reject averaged KL (three failures, independent reward SGD still passes), a detached reward (three failures, reward SGD passes), and reference-gradient leakage (both regularized cases fail; zero-beta and reward SGD pass). Selecting flow parameters instead of LM parameters fails the public ownership test because the policy does not update. These are deliberate mutations of the new method, not invented before/after numerical failures for an API that did not previously exist.

Build59 passes both production library builds with zero errors. The production-only linked suite passes all 520 cases. The actual repository test project compiles and passes the same complete 520-case suite on each of net8.0 and net471, with zero failures or skips. SHA-256 checks verify that each target's copied test library equals its corresponding production build; the checkpoint-audit tool builds with zero warnings or errors. All 18 requested model classes and unrelated work are preserved. No original private reward checkpoint or training-corpus convergence is claimed.
